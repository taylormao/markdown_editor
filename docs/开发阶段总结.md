# Folio 1.5.0 开发阶段总结（代码心智图谱）

**一句话定位**：本地优先的沉浸式 Markdown 写作台。CodeMirror 6 编辑核心 + 自研全局状态机 + YAML frontmatter 元数据 + 双链 + PARA 目录 + 四视图（写作/预览/大纲/导图）。

## 二、数据模型（src/types.ts + workspace-io）

- **WorkspaceSnapshot**：`folders / sheets / activeFolderId / activeSheetId / openTabIds / theme / tracking / disabledSystemFolderKeys`（版本 v3）
- **Sheet**：`id / folderId / title / content / createdAt / updatedAt / starred`——正文是"markdown 字符串 + frontmatter"，标题从 YAML 或首行提取
- **SearchResult**：检索结果类型
- **持久化双通道**：`localStorage['folio.workspace.v1']` 缓存 + `PUT /api/workspace` 落盘；`keepalive` 应对页面关闭。服务端写 `data/workspace.json`（tmp+rename 原子写），写前先备份旧文件到 `workspace.backup.json`；主文件损坏 → backup → seed 三级恢复。

## 三、状态机（workspace-store/）——项目的心脏

模块级单例 + `useSyncExternalStore`，**无 React context**。v1.5.0 起切片化为 7 个 slice 工厂 + 组装层。核心机制：

- `setState(patch, persist)`（core.ts）：不可变更新 + 广播 + 可选防抖持久化（420ms 防抖 + 1600ms "已保存"回落）
- `persistSoon()`：saving → saved → idle 三态保存指示器
- **slice 工厂模式**：每个 slice `createXSlice(ctx)` 返回 `satisfies Partial<WorkspaceActions>`；跨族调用走 `ctx.actions.X` 延迟解析；state 走 `ctx.get()/ctx.set()` 实时读取；危险操作走 `ctx.runProtected` 密码门

### Slice 职责划分

| slice | 职责 | 主要动作 |
|---|---|---|
| `chrome` | 视图/UI/密码门/YAML/rename/caret/模式循环 | `setView` `setChromeMode` `cycleChromeMode` `openYamlEditor` `setSuperPassword` `submitPassword` `setCaret` `openAtLine` `requestRename` 等 |
| `folders` | 目录创建/重命名/删除 | `createFolder` `requestCreateFolder` `renameFolder` `deleteFolder` `requestDeleteFolder` |
| `manage` | 管理模式扁平列表/展开折叠/确认 | `moveManage` `toggleManageExpand` `collapseManage` `expandManage` `confirmManage` `currentManageItem` |
| `navigation` | 选择文稿/文件夹/关闭标签/双链打开 | `selectSheet` `selectFolder` `openWiki` `openSheetByTitle` `closeTab`（含 `blockLeave` 校验拦截） |
| `templates` | 快速新建/模板两级选择/创建文稿 | `requestQuickSheet` `requestNewSheet` `createSheetFromTemplate`（type→模板两级，新稿进收集箱，daily 去重） |
| `sheets` | 文稿操作：重命名/移动/分类/软删除/星标/内容更新 | `renameSheet` `moveSheet` `classifySheet` `deleteSheet` `applyFrontmatter` `updateSheetContent` `toggleStar` |
| `workflow` | 结束写作/启动归类/继续编辑 + 持久化 | `prepareFinishWriting` `finishWriting` `classifyPending` `openContinued` `closeStartup` `hydrate` `exportBackup` `importBackup` |

### 关键动作族（跨 slice 协作）

| 族 | 动作 |
|---|---|
| 选择 | `selectSheet/selectFolder/openWiki/openAtLine/nextTab`（含 `blockLeave` 校验拦截，helpers.computeIssues） |
| 新建 | `requestQuickSheet/requestNewSheet/createSheetFromTemplate`（type→模板两级，新稿进收集箱，daily 去重） |
| 跟踪 | `beginTracking/markTouched/prepareFinishWriting/finishWriting/classifyPending`（指纹工作流） |
| 危险操作 | `runProtected`（统一走密码门）：移动/建子目录/重命名/删除/删系统文件夹 |
| 模式 | `setChromeMode/cycleChromeMode`（edit→select→manage 循环） |
| 管理 | `moveManage/collapseManage/expandManage/confirmManage/currentManageItem` |

### 指纹工作流（收集箱非 spark 稿）

- `canonicalSheet` = title + frontmatter(去 updated) + body → SHA-256
- `baselineFingerprint`（编辑前基线）→ `touched`（编辑标记）→ 结束时重算：相同=撤销干净（清跟踪），不同=进归类清单
- **只读操作不触发 touched**；标题/正文/YAML 变化才触发

## 四、编辑层（CodeMirror 6，14 扩展装配）

**核心设计**：frontmatter 前缀与正文分离——编辑器只编辑 `body`，`onChange` 时拼回 `prefix + body`；光标通过 `locateLogical` 在完整文档坐标和逻辑行间换算。

**扩展清单**：history / markdown(lang-data) / folioEditorTheme+Highlight / placeholder / keymap（Esc 透传 store、Mod-k 链接、Mod-l 任务、Mod-y YAML、default/history/search/indentWithTab）/ lineWrapping / superSyntax / mathSyntax / liveBlocks / wikiSyntax / calloutDecor / updateListener（doc 变化→store，caret 追踪，slash/wiki 会话检测）。

**实时块渲染（live-blocks）**：正则扫描闭合代码围栏/表格/Mermaid → `Decoration.replace` 整块替换为渲染 widget；**光标进入块内时恢复源码**（`selectionInside` 检查）；Mermaid 用 `securityLevel: 'strict'` 防 XSS。table 用 mousedown 定位回源码。

**斜杠菜单**：`/` 触发 → 三模式（list 命令 / table 尺寸选择 2-12 行列 / code 语言），`/code/python` 路径式筛选，19 个命令（表格/代码/Mermaid/脚注/callout×5/公式×2/超级样式×5/上下标/引用），脚注自动编号。

**超级语法**：`==[-b -i -d -c=red -bgc=yellow -yuan -fang]文字==`、`==up2==`/`==downH2O==`、`[-yuan]5` 圆圈数字映射 ①-⑳。

## 五、渲染层（render-markdown.tsx）——自研而非 marked/markdown-it

**为什么自研**：为了和编辑器 widget 渲染完全一致（callout、super-syntax、双链、数学），且 0 依赖。

- **块解析器** `parseBlocks`：heading/paragraph/quote(callout 识别)/code/mermaid/list(task checkbox)/table/hr/footnote/math($$)/fence
- **行内 tokenizer** `tokenizeInline`：code/math/`==`super/`[[wiki]]`/image/link/footnote/strong/em/strike，逐前缀匹配循环
- **双链显示**：`displayWiki(ref, sheets)` 按 id 或 content 匹配标题，chip 可点击跳转
- **Callout**：`[!NOTE|INFO|TIP|WARNING|ERROR|DANGER]` → 中文标签 + 彩色 blockquote
- **安全**：CodeBlock 用 highlight.js escape；Mermaid 严格模式；KaTeX `throwOnError:false`；图片/链接 `target=_blank rel=noreferrer`

## 七、关键设计决策（代码中可见的约束）

1. **自研 YAML 解析器**（frontmatter.ts）——不用 js-yaml，避免依赖，支持标量/列表/嵌套对象，序列化带安全引号
2. **前端逻辑可在无 API 时独立运行**（storage fallback to localStorage）——服务端只是"落盘器"
3. **删除=软删除**：移到 999-未分类 + `status: trashed`，不销毁
4. **双链用稳定 id 存储**：`[[标题]]` 保存时规范为 `[[20260812-video-xxxx]]`，界面回显标题
5. **blockLeave 拦截**：必填字段缺失（validateDoc）时禁止切换文稿，YamlIssues 常驻提示
6. **Esc 优先级链**：密码门→模板选择→结束写作→启动步骤→YAML 编辑器→chrome 模式循环（且 slash/wiki 菜单用 stopPropagation 独立处理）
7. **逻辑行**：`logical-line.ts` 把代码围栏/公式块/表格/引用块视为"一个逻辑行"，状态栏行号按逻辑行计

---

**总结**：这是一个"**自研小生态**"型应用——Markdown 解析、YAML、状态管理全部手写，只有 CodeMirror/KaTeX/Mermaid/highlight.js 是外部依赖。架构上**纯逻辑层（lib）与 UI 完全解耦**，状态机是唯一真源（single source of truth），所有组件通过 `useWorkspace()` 订阅。v1.5.0 起状态机已切片化为 `workspace-store/` 目录（core/tracking/helpers/types + 7 个 slice 工厂），核心难点集中在 slices（工作流状态机）和 render-markdown（与编辑器渲染对齐的自研解析器）。
