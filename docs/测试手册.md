# Folio 测试手册

本文档对应 Folio **1.4.0**（PARA 文件组织 + 收集箱工作流 + 超级密码 + 软删除 + 指纹追踪 + 稳定双链）的测试体系。测试覆盖三个层次：单元测试、Store 集成测试和浏览器 E2E 测试，并提供一个一键运行全部测试的脚本。

## 1. 测试层次总览

| 层次 | 目录 | 运行器 | 环境 | 用例数 |
|---|---|---|---|---|
| 单元测试 | `test/unit/*.test.ts` | Vitest | jsdom | 见下文各文件 |
| Store 集成测试 | `test/store/workspace-store.test.ts` | Vitest | jsdom + MemoryStorage | 同上 |
| E2E 测试 | `test/e2e/folio.spec.ts` | Playwright | 真实 Chromium + Vite dev server | 10 |

单元与 Store 测试（Vitest）约 **109** 条断言全部通过；E2E **10/10** 通过。

## 2. 运行方式

### 2.1 全部测试一键运行

```bash
npm run test:all        # 先单元/集成（Vitest），再 E2E（Playwright）
```

### 2.2 分层运行

```bash
npm run test            # 等价于 vitest run：单元 + Store 集成测试
npm run test:unit       # 同上，明确命名
npm run test:e2e        # 等价于 playwright test：E2E
```

### 2.3 测试套件入口脚本

```bash
node scripts/test-suite.ts          # 全部测试（同 npm run test:all）
node scripts/test-suite.ts --unit   # 仅单元/集成
node scripts/test-suite.ts --e2e    # 仅 E2E
```

脚本会先检查依赖（`vitest` / `@playwright/test` 是否已安装），依次执行测试，最后汇总结果并设置退出码（全绿为 0，任一失败为 1），适合接入 CI。

### 2.4 前置条件

- Node.js ≥ 20（开发环境实测 Node v26 通过）
- 已执行 `npm install`
- Playwright Chromium 已安装：`npx playwright install chromium`
- E2E 需要 Vite dev server；`playwright.config.ts` 配置了 `webServer`，会自动启动（`reuseExistingServer: true`，若 5173 端口已有服务则直接复用）

## 3. 单元与 Store 集成测试（Vitest）

配置见 `vitest.config.ts`：

- `environment: 'jsdom'`，`setupFiles: ['test/setup.ts']`（提供 `localStorage`/`sessionStorage` 的 MemoryStorage polyfill）
- 只收集 `test/unit/**/*.test.ts` 与 `test/store/**/*.test.ts`
- 单测超时 15 秒

## 4. E2E 测试（Playwright）

配置见 `playwright.config.ts`：

- `testDir: 'test/e2e'`，`baseURL: http://127.0.0.1:5173`
- `workers: 1`（顺序执行，测试共享同一服务端状态）
- `headless: true`，失败时保留 trace（`test-results/*/trace.zip`，可用 `npx playwright show-trace` 查看）

### 4.1 测试自包含的确定性 seed

E2E 不依赖 `data/workspace.json` 的当前内容（该文件可能被手动使用或上次运行写脏）。`test/e2e/seed.ts` 定义了完整的确定性工作区快照：

- 15 个 PARA 文件夹（含固定 systemKey：`inbox`、`project`、`daily` 等）
- 5 篇 seed 文稿：
  - `20260819-daily-7lk6`（daily，标题「2026-08-19 晚间」，位于收集箱）
  - `1bc50446-94b0-4d81-9dc9-1e096ae148b2`（spark，标题「一个尚未展开的念头」，位于收集箱）
  - `20260819-project-tvch` / `20260819-project-w7u0`（project 模板文稿，位于收集箱，用于干扰「按内容找新建稿」的误匹配）
  - `452c67c6-57bc-452f-9e80-ea14b565bd41`（spark「把思想写成作品」，位于 999-未分类）
- `beforeAll` 将 seed 写入服务端，`beforeEach` 完整还原（文件夹/文稿/tracking/激活状态全部复位），保证每个用例互不污染。

### 4.2 启动弹窗处理

seed 的 tracking 为空，正常加载不会弹启动弹窗；但保险起见 `beforeEach` 调用 `dismissStartupDialog`：若出现 classify → continue 两个连续弹窗，循环点击「暂不处理」直到无弹窗，并断言 `.template-mask` 遮罩消失。

### 4.4 E2E 关键实现细节（踩坑记录）

- **420ms 防抖落盘**：app 对服务端快照的持久化有约 420ms 防抖。UI 操作后立即读服务端会拿到陈旧快照，涉及「新建」「归类」的断言必须用 `expect(...).toPass({ timeout: 10000 })` 轮询。
- **`pagehide` 覆盖服务端数据**：App 在 `pagehide` 时用内存中的空 tracking 覆盖服务端（`saveWorkspace(currentSnapshot(), keepalive=true)`），且 `page.route` 拦不住 unload 时的 keepalive fetch。因此「启动待归类清单」用例用 `context.newPage()` 开全新页面加载，旧页面不卸载即不触发 pagehide。
- **ContextMenu portal 化**：`.glass-rail` 的 `backdrop-filter` 会创建包含块/层叠上下文，`fixed` 定位的上下文菜单被限制在侧栏内，flyout 延伸进编辑区会被编辑区拦截。已通过 `createPortal(document.body)` 修复；测试（用例 6）同时起到回归作用。
- **选择器歧义**：工具栏「写作/预览/大纲/导图」按钮必须用 `getByRole('button', { name: ..., exact: true })`，避免匹配编辑器正文或「结束写作」等相近文本。
- **`page.evaluate` 传参**：`page.evaluate` 内不能引用 Node 作用域常量，需作为参数传入（如 `page.evaluate((api) => fetch(api).then((r) => r.json()), API)`）。
- **定位新建稿**：seed 收集箱中已有 project 模板文稿，不能按 `content.includes('template: project')` 找新建稿，必须用 `snap.activeSheetId`。

## 5. 新增测试指引

- **单元/Store**：在 `test/unit/` 或 `test/store/` 下新建 `*.test.ts`，Vitest 会自动收集；需要 DOM 存储时利用 `test/setup.ts` 的 polyfill。
- **E2E**：在 `test/e2e/folio.spec.ts` 追加用例。若用例需要新的 seed 文稿或文件夹，先修改 `test/e2e/seed.ts` 保证确定性；涉及服务端落盘断言的，套用 `toPass` 轮询模式。

## 6. 常见问题排查

| 现象 | 处理 |
|---|---|
| E2E 报「No tests found」 | 检查 `test/e2e/seed.ts` 是否存在（spec 依赖该 fixture）；确认 testDir 正确 |
| E2E 断言收到陈旧快照 | UI 操作后立即读服务端是防抖前的旧值，改用 `expect(...).toPass()` 轮询 |
| 启动弹窗测试不稳定 | 确认使用 `context.newPage()` 全新页面，且预置 pending 前等待 700ms 让 beforeEach 残留防抖落盘 |
| Vitest 报 localStorage 未定义 | 确认 `test/setup.ts` 已作为 `setupFiles` 加载 |
| Playwright 找不到浏览器 | 执行 `npx playwright install chromium` |
| 端口 5173 被占用 | `reuseExistingServer: true` 会直接复用已有 dev server；若复用的是陈旧进程，手动重启后再跑 |
